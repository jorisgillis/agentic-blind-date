# 0003: Consistent Interview Experience for All Participants

## Status
Accepted

## Context
The application currently has **three different interview paths** for participants:

1. **GitHub users with successful LLM**: FixedQuestions + 3 custom LLM-generated questions
2. **GitHub users with failed LLM**: FixedQuestions + 3 hardcoded fallback questions
3. **Non-GitHub users**: ExtraQuestions + FixedQuestions (minus fixed_1)

This inconsistency creates:
- Different data collected from different participants
- Different user experiences
- Potential confusion for participants
- Harder to maintain and test

The custom questions for GitHub users are generated by LLM based on their profile, with the intent of asking more personalized, relevant questions. However, when LLM generation fails, these users get a different set of questions than non-GitHub users.

## Decision
We will **standardize the fallback questions** for GitHub users to match the `ExtraQuestions` used for non-GitHub users.

### Implementation
When LLM custom question generation fails for a GitHub user:
- **Current**: Return hardcoded questions (lines 107-111 in agents.go)
- **New**: Return `ExtraQuestions` from questions.go

This ensures:
- All participants who don't get LLM-generated questions receive the same questions
- The questions capture the same information (languages, project types, dev environment, etc.)
- The experience is consistent and predictable

### Question Sets

**FixedQuestions** (all participants):
- Tabs or spaces?
- What's your go-to language right now?
- Would you deploy on a Friday?
- Monolith or microservices?
- Your git commit style?
- Which AI coding assistant do you prefer?

**ExtraQuestions** (fallback for GitHub users, primary for non-GitHub users):
- What are your top 3 programming languages?
- What type of projects do you most enjoy working on?
- What's your preferred development environment?
- What's the weirdest bug you've ever fixed?
- Keyboard preference?

**Custom Questions** (GitHub users with successful LLM generation):
- 3 personalized questions based on GitHub profile

### Combined Interview
- **GitHub users (LLM success)**: FixedQuestions + CustomQuestions (6 total)
- **GitHub users (LLM failure)**: FixedQuestions + ExtraQuestions (11 total)
- **Non-GitHub users**: ExtraQuestions + FixedQuestions (11 total)

Note: GitHub users with LLM success get fewer questions (6) than others (11). This is intentional as the custom questions are designed to be more informative and replace the need for some of the ExtraQuestions.

## Consequences

### Good
- **Consistency**: All participants without LLM-generated questions get the same questions
- **Predictability**: The fallback path is well-defined and consistent
- **Maintainability**: Fewer code paths to maintain
- **Data completeness**: ExtraQuestions capture comprehensive profile data for non-GitHub users

### Bad
- **Question count inconsistency**: GitHub users with LLM success answer fewer questions (6) than others (11)
- **Redundancy**: GitHub users may be asked about languages twice (once in FixedQuestions, once in ExtraQuestions if LLM fails)

## Alternatives Considered

### Alternative 1: All Participants Get ExtraQuestions
Remove custom questions entirely, all participants get FixedQuestions + ExtraQuestions.
- **Pros**: Completely consistent, simpler
- **Cons**: Loses personalization benefit of custom questions
- **Decision**: Rejected; custom questions add value for GitHub users

### Alternative 2: Non-GitHub Users Get Custom Questions Too
Generate custom questions for non-GitHub users based on their ExtraAnswers.
- **Pros**: All participants get personalized questions
- **Cons**: More LLM calls, complexity
- **Decision**: Rejected for now; current approach is sufficient

### Alternative 3: Remove FixedQuestions for Non-GitHub Users
Non-GitHub users only get ExtraQuestions.
- **Pros**: Fewer questions for non-GitHub users
- **Cons**: Different data collected, harder to compare participants
- **Decision**: Rejected; FixedQuestions provide valuable standardized data

### Alternative 4: Make Custom Questions Fallback to ExtraQuestions
When LLM fails, use ExtraQuestions instead of hardcoded questions.
- **Pros**: This is the chosen approach
- **Cons**: None significant
- **Decision**: Accepted

## Future Considerations

1. **Dynamic question selection**: Based on participant type, select appropriate questions dynamically
2. **Question weighting**: Weight answers differently based on question type
3. **Adaptive interviewing**: Ask follow-up questions based on previous answers
4. **Question analytics**: Track which questions produce the best matches
